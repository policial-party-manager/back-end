## What to build

把签到从「管理员在后台点名单」变成「现场投屏二维码，成员自己扫」。

现在扫码签到是不存在的：文档要求支委点一下生成二维码，二维码 60 秒自动失效刷新以防截图转发，成员扫码即可完成签到，签到人数实时增加。

做完之后：支委为进行中的活动生成二维码，返回一个时效 token 与过期时间；token 默认 60 秒失效并自动刷新，有效期可配置。一张有效的二维码可以被现场所有参与者扫，不是一人一码——它证明的是「此刻在场」，不是「谁抢到了」。防重复靠参与者与活动的唯一性，不靠 token 一次性。扫过期或伪造的 token 被拒绝。

不做地理围栏。

## Acceptance criteria

- [ ] 支委能为进行中的活动生成签到二维码，返回 token 与过期时间
- [ ] token 默认 60 秒后失效，有效期可配置
- [ ] 过期后旧 token 无法用于签到，重新生成后可继续签到
- [ ] 同一张有效二维码可以被多个不同参与者分别扫码签到成功
- [ ] 同一个人用同一张二维码重复扫码，收到「您已完成签到」一类的明确提示
- [ ] 使用伪造或无效 token 签到被拒绝
- [ ] 普通成员无法生成二维码
- [ ] 支委只能为本支部活动生成二维码，跨支部被拒绝
- [ ] 签到成功后，该活动的签到人数立即反映在统计里
- [ ] 活动未到签到时间、已过截止时间、已结束时，扫码签到收到各自的明确提示
